# Codex Menu

在 macOS 顶部菜单栏查看多个本机 Codex 会话的公开进度。原生 Swift / AppKit 实现，没有第三方依赖，不需要 API Key。

![界面示意，使用示例会话](preview.png)

## 使用

双击 `dist/Codex Menu.app`。应用只出现在菜单栏，不占用 Dock。

- 每个展开会话使用一个独立的 macOS NSStatusItem 和系统原生 NSStatusBarButton，直接绑定对应会话，拥有各自的右键进度卡片；总入口也是独立图标。进度绘制层不接收点击，文字更新不会更换图标绑定的会话。
- 统一使用中性背景：深色主题为较浅的石墨灰，浅色主题为雾白；标题和进度使用不同文字层级，并保留细分隔线。长进度文字会在固定宽度区域内滚动，标题始终可见。
- 左侧圆灯以约 1.6 秒一周期柔和闪烁黄灯，表示运行中；红灯常亮表示错误；以约 2 秒一周期闪烁绿灯，表示本轮已完成。等待操作与中断为黄灯常亮，状态待核实为灰灯常亮。状态同时显示文字，颜色不是唯一提示。
- 已完成条目保留到你点击打开对应会话。
- 点击已完成、出错或中断的条目，只收起所点击的那一条；其他会话继续保留。
- 点击运行中的条目会打开对应会话，进度条继续显示。同一个会话开始新一轮任务时会再次出现。
- 悬停或关闭滚动只暂停文字，状态灯仍可闪烁。状态灯使用 Core Animation 独立绘制，进度每两秒更新时不会重新开始闪烁。系统开启“减少动态效果”时停止文字滚动、状态灯闪烁和弹层进出动画，状态灯保持常亮。
- 总入口参考 [Codex Status Bar](https://github.com/yuriipalam/codex-status-bar) 的原生菜单组织方式：按“需要操作 / 正在进行 / 已完成与保留”分组，显示会话状态和可选的运行计时。菜单展开期间继续刷新进度、计时与点击目标；支持原生键盘操作。运行中的条目优先展开，溢出会话始终保留在总入口。
- 从总入口的“设置…”打开独立设置窗口。菜单栏字号支持 10–15 pt，进度卡片及会话列表字号支持 11–20 pt，均以 0.5 pt 调整；设置中有使用实际视图绘制的预览。进度卡片随文字大小增加宽高，公开进度可滚动与复制。
- 可调整每条宽度（180–480 pt）、最多展开条数（1–6 条）、标题显示、滚动开关与速度（12–60 pt/s）、运行计时、柔和灯光动画，以及跟随系统 / 浅色 / 深色外观。菜单栏实际可用空间由 macOS 管理；每个会话保持设置的宽度，空间不足时从总入口查看未展开会话。设置即时生效并自动保存，旧版本宽度、条数、滚动设置及保留会话会自动迁移。菜单“选项”和“外观”中也提供常用快捷设置。
- 右键或 Control＋点击会话图标，会在该图标下方以原生动画展开进度卡片，显示状态、更新时间、完整标题和最新公开进度。进度区域可选取、复制和滚动；卡片打开期间会继续更新同一会话。点击外部或按 Esc 收起；切换图标时换成对应会话的卡片。右键本身不会打开或收起会话条目。
- 卡片提供“打开此会话”和“全部会话与设置”两个独立按钮。总入口采用原生紧凑分组，完整显示与交互选项集中在“设置…”窗口。
- 可以按住 ⌘ 分别拖动会话图标和总入口；各图标独立保存位置。图标排列、可见性与是否被其他菜单栏工具折叠由 macOS 和相关工具管理。
- 退出时保留条目与设置；再次启动后恢复。“登录后启动”默认关闭，可在设置中通过 macOS 登录项服务启用；如系统要求批准，窗口会显示前往系统设置的入口。

默认每 2 秒读取一次。启动前已结束的历史会话不会批量加入；启动后完成的会话会保留，包括两次轮询之间完成的短任务。

## 状态与文字来源

只读打开 `$CODEX_HOME`（默认 `~/.codex`）中的 `state_5.sqlite` 和 `thread_history_1.sqlite`，并增量读取会话元数据指向的 JSONL 运行日志。恢复会话或日志切换文件时，历史数据库索引可能停留在旧轮次；实时日志中的新轮次和结束事件用于纠正这一情况。读取会话名称、最近一轮的明确状态、公开的 commentary / final 消息，以及命令、文件修改、工具调用等通用状态。跳过子代理会话。

不提取或展示 reasoning 的正文、摘要、工具参数、命令正文或命令输出，不调用模型生成“思考过程”。日志解码器只保留轮次标识、时间、生命周期事件和公开进度；遇到 reasoning 条目时仅用其所属轮次和事件时间确认活动，不解码其内容。工具进度只显示操作类型及工具名。记录长时间未更新时显示“状态待核实”，不会据此宣称任务完成。明确的失败与中断分别使用红色和琥珀色，并有文字及图标说明。

当前版本针对本机保存的 Codex 会话。它不修改 Codex 客户端及左侧会话列表，也不连接 SSH 主机或云端会话。等待状态仅在本地记录明确标记时显示；不能保证识别所有授权弹窗或待输入状态。

使用的 SQLite 布局和运行日志格式是在 ChatGPT / Codex `26.1021.31345` 上核对的本地实现细节，后续客户端版本可能需要更新适配。数据库格式不兼容或读取失败时，总入口显示警告并保留上次记录；此时应进入会话核实当前状态。首次读取大日志仅加载末尾最多 2 MiB，随后只读新增字节；日志缺失或无法识别时回退到数据库。

条目通过 `codex://threads/<id>?hostId=local` 打开。已核对本机客户端接受这一会话路由。链接明确交给当前运行的 `com.openai.codex` 应用处理；没有运行实例时再查找已安装的应用。不会依赖系统默认 URL 处理器，也不沿用客户端当前选择的远程连接。使用异步打开接口，只有系统回报成功后才收起所点击的已完成轮次；如果期间开始了新轮次，新轮次继续保留。系统报告失败时弹出错误并保留条目。系统回报成功仅代表链接已交给目标应用，无法确认目标页面最终加载成功；Codex 禁止界面自动化访问，因此目标页面仍需用户端核对。

自身状态保存在 `~/Library/Application Support/CodexMenu/state.json`，包含保留条目的名称、公开进度和状态。没有网络请求、会话写入、配置注入或通知权限要求。运行计时仅使用当前轮次明确的开始时间；日志尾部没有开始记录且索引不能对应时不显示计时，不会将首次观测时间当作任务开始时间。

## 构建与检查

需要 macOS 13+ 和包含 Swift 的 Xcode / Command Line Tools。默认构建当前机器架构；GitHub 发布附件为同时包含 Apple Silicon 与 Intel 的 Universal 2 版本，签名为本地 ad-hoc 签名。下载及命令行安装见[仓库首页](../README.md)。

```sh
zsh scripts/build.sh
```

输出 `dist/Codex Menu.app`。构建缓存写入项目内的 `.build`。

应用图标使用 `Resources/AppIcon.png` 的 1024 × 1024 原图。构建时会自动生成包含标准与 Retina 尺寸的 `AppIcon.icns`，写入应用包的 `Contents/Resources`，并由 `Info.plist` 引用；Universal 2 发布包使用同一流程。修改原图后重新构建即可更新图标，无需另装图像处理依赖。

菜单栏总入口和设置窗口标题旁使用同一应用图标；读取失败时，总入口显示警告符号。会话条目继续使用各自的状态灯。

```sh
env CLANG_MODULE_CACHE_PATH="$PWD/.build/clang-module-cache" \
  swift test --disable-sandbox --cache-path .build/cache \
  --config-path .build/config --security-path .build/security
```

测试覆盖完成条目的保留与独立收起、新任务重新出现、短任务捕获、旧历史过滤、跨重启恢复、实际 SQLite 读取、推理与工具内容排除、数据库只读保护，以及索引滞后、部分写入、日志切换和大文件尾部读取。交互测试为不同会话创建不同的真实 NSStatusItem，检查系统按钮、独立事件目标、绘制层不拦截点击、点击到对应 URL 的完整链路、原生右键及 Control＋点击路由；还检查字体和宽度更新、会话换序、邻居移除后按钮绑定保持正确，以及无展开会话时总入口仍能打开列表。通过 NSApplication 事件队列向真实菜单栏窗口投递完整按下／松开事件，验证不同会话打开各自的预览、预览在松开后保持可见。总入口测试实际展开 NSMenu，再触发真实“设置…”菜单项并检查设置窗口可见。布局检查验证宽度预算和溢出规则。还检查原生进度卡片的数据更新和按钮绑定、红灯常亮、减少动态效果、文字暂停后状态灯仍工作，并在独立 AppKit 窗口采样实际显示层的透明度，验证状态灯确实明暗变化。另有指定应用打开、错误回报，以及异步跳转期间新任务开始的检查。设置检查覆盖旧状态迁移、字体及主题持久化、最大字号下的实际文本视图和滚动区域、独立按钮绑定、灯光关闭与运行计时来源。

菜单栏点击由每个 NSStatusItem 自带的系统原生按钮处理，不使用组合容器或共享事件监视器。右键预览和菜单在鼠标松开后的下一轮主队列显示，避免触发点击立即关闭新弹层。

命令行辅助功能：

```sh
# 读取当前本机状态，不启动菜单栏界面
"dist/Codex Menu.app/Contents/MacOS/CodexMenu" --snapshot

# 用隔离的示例数据体验；演示模式不写入真实保留状态
"dist/Codex Menu.app/Contents/MacOS/CodexMenu" --demo

# 指定数据源或自身状态文件（例如用于测试）
"dist/Codex Menu.app/Contents/MacOS/CodexMenu" \
  --codex-home /path/to/codex-home --state-file /path/to/menu-state.json

# 渲染界面示意，使用示例会话，不是屏幕截图
"dist/Codex Menu.app/Contents/MacOS/CodexMenu" --render-preview /tmp/codex-menu.png

# 渲染设置窗口；可追加 --dark 或 --large-font
"dist/Codex Menu.app/Contents/MacOS/CodexMenu" --render-settings-preview /tmp/codex-menu-settings.png
```

若已有一个菜单栏实例在运行，普通启动会复用原实例，不创建重复条目。要切换演示模式或命令行参数，请先从菜单退出旧实例。

## 设计与扩展依据

官方[插件文档](https://learn.chatgpt.com/docs/plugins)列出了 skills、MCP servers、hooks 等扩展方式，没有给出将桌面侧栏替换为 macOS 菜单栏的接口，因此本项目使用独立原生应用。

官方 [App Server 文档](https://learn.chatgpt.com/docs/app-server)提供会话状态与流式事件。若以后改用 App Server，需要连接承载目标会话的服务；另起一个进程不意味着能获得现有桌面进程的实时状态。本版本只读适配本地数据库和运行日志，未尝试接管或恢复会话。

菜单与设置的设计参考及上游 MIT 声明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。保留原有三色状态灯、独立会话按钮、本地读取方案与完成保留规则。
